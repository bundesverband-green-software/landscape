# AGENTS.md — Green Software Landscape

Content repository for the Bundesverband Green Software
tool landscape (<https://landscape.bundesverband-green-software.de>). There is no
application code here: the site is generated from YAML by the CNCF
[landscape2](https://github.com/cncf/landscape2) tool.

## Golden rule

Edits belong in the **YAML source files** (`data.yml`, `settings.yml`, `guide.yml`)
and `logos/`. `build/` and `cache/` are generated and gitignored — never edit or
commit them.

## Key files

| File            | Purpose                                                              |
|-----------------|----------------------------------------------------------------------|
| `data.yml`      | All tools + the category/subcategory tree. The file you touch most.  |
| `settings.yml`  | Site config: colors, groups, featured items, header/footer links.    |
| `guide.yml`     | Content of the in-site guide. Contains **German and English** text.  |
| `logos/`        | Tool logos (see below).                                              |
| `.github/workflows/deploy.yaml` | CI: builds with landscape2 and deploys to GitHub Pages on push to `main`. |

## Adding or editing a tool (`data.yml`)

A tool is an `- item:` entry inside a subcategory's `items:`. Every tool lives in
exactly one category; `second_path` lists additional places it appears.

Required fields:

```yaml
- item:
  name: Tool Name
  description: One or two short plain-text sentences. No Markdown/HTML.
  homepage_url: https://example.com/
  logo: toolname.svg
```

Optional fields:

- `repo_url` — source repository
- `blog` — blog/news URL
- `license` — usually **not set manually**: landscape2 fetches it from GitHub.
  Set it explicitly only when the license cannot be fetched (e.g. no repo, or
  `repo_url` missing).
- `project` — maturity flag, one of `"archived"` or `"in-active-use-by-members"`.
  Only these two values exist. `"in-active-use-by-members"` means the tool is
  used in practice by BvGS member organizations; `"archived"` greys it out.
  `project` is **not** CNCF-style maturity.
- `second_path` — list of `"Category / Subcategory"` strings. Both parts must
  match existing names in `data.yml` exactly.
- `extra.documentation_url` — link to user/methodology docs

Keep YAML indentation consistent with neighbouring entries (2-space steps).
Multi-line descriptions use the `|` block scalar.

Gotcha: a **new top-level category** must also be added to a `groups:` entry in
`settings.yml`, or it will not render on the site.

## Logos

Logo paths are relative to `logos/`:

- Root `logos/` — tool has its own logo. Prefer SVG, then PNG.
- `logos/organization/` — no tool logo; use the parent organization's logo.
- `logos/unofficial/` — generated text-only placeholder. Legacy ones are Impact
  outlines from <https://text-to-svg.com/>; new ones are generated by the
  `add-logo` skill (Roboto Condensed, black glyph outlines).

New logo filenames are **lowercase kebab-case** (e.g. `green-metrics-tool.svg`),
including initials and punctuation (`CO2.js.svg` → `co2-js.svg`).

## Validate (do this before finishing any YAML change)

```sh
landscape2 validate data     --data-file data.yml
landscape2 validate settings --settings-file settings.yml
landscape2 validate guide    --guide-file guide.yml
```

## Build & serve locally

```sh
landscape2 build \
  --data-file data.yml \
  --settings-file settings.yml \
  --guide-file guide.yml \
  --logos-path logos \
  --cache-dir cache \
  --output-dir build

landscape2 serve --landscape-dir build
```

`GITHUB_TOKENS` (scope `public_repo`) is optional; without it GitHub-derived
info is missing from the local build.

## Contribution conventions

- Proposals/new tools arrive via the **Tool Proposal** issue template and must
  meet the prerequisites documented in `README.md` (green-software relevance,
  publicly available + functional, user docs, methodology docs).
- Pull requests use `.github/pull_request_template.md` and should explain how
  the tool's methodology is documented.
- `description` fields and docs are English; `guide.yml` mixes German and
  English. Match the language of the file you edit.
